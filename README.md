# myzcanpro — UDS 诊断 / ECU 刷新上位机

基于 ZLG(USBCANFD / USBCAN-II)的自研诊断上位机,界面仿 ZCANPro。

## 运行(源码)
需 **32 位** Python(zlgcan.dll 是 32 位)+ PyQt5。ZCANPro 自带的 `python38` 即可:
双击 `run.bat`(路径不同时先设置环境变量 `PY32`)。
不接硬件时,通道选"模拟ECU(测试)"即可体验全部流程。

## 打包成绿色软件
- 本地:双击 `build.bat` → `dist\myzcanpro\myzcanpro.exe`(整个文件夹拷走即可)。
- 云端:推送到 GitHub 后由 `.github/workflows/build.yml` 构建,在 Actions 的 Artifacts 下载。

## 设备管理(主界面)
1. 下拉选择设备(USBCANFD 系列 / USBCAN-II / 模拟ECU),点「打开」→ 按钮变为「关闭」(只能在两种状态间切换)。
2. 打开成功后出现各通道行,点「启动」弹出配置:CAN/CAN FD、波特率(kbaud/s)、正常/只听、终端电阻、是否计算总线负载率(刷新时间默认 200 ms)。
3. 通道启动后,主界面实时显示接收/发送/错误帧数和总线负载率;UDS诊断、ECU刷新窗口里的「通道」下拉只列出已启动的通道。

## 部署目录(与 exe 同级)
- `zlgcan.dll` 与 `kerneldlls\`:仓库 `vendor\` 里已带官方 SDK(zlgcan_x86,2026-10 版),打包时自动复制到 exe 旁;
  源码运行时程序也会自动在 `vendor\` 里查找。官方头文件在 `docs\zlgcan_sdk_headers\`。
- 公司密钥 dll 及其依赖;需安装 VC++ 2013 x86(zlgcan)、VC++ 2008 x86(密钥 dll)运行库
- 程序运行后自动生成:`myzcanpro_config.json`、`services.json`、`error.log`、`logs\`

## 例程控制(31)
ECU刷新里选 31 服务后，先选「例程类型」，标识符(2 字节)、子服务(01/02/03)都由你填写：
- **擦除内存**: `31 [子服务] [标识符] [44] [起始地址] [大小] [扩展字节]`。格式字节高4位=大小长度、低4位=地址长度(与 ISO 14229 一致，默认 0x44)；
  起始地址、大小取自烧写文件，整个流程只执行一次；扩展字节(默认 01)可编辑或取消；大小可选「各段长度之和」(默认，与校验码工具的总长度一致)或「首段起始到末段末尾」。
- **CRC校验**: `31 [子服务] [标识符] [校验码]`。可选 *分段CRC*(每段传输结束后立刻校验，烧录结束后再做一次全文件CRC) 或 *全文件CRC*(只在烧录结束后校验一次)；
  全文件CRC 为各段按顺序拼接后的校验值。CRC 类型/字节序可配。
- **更新条件查询 / 自定义例程**: 任意 `31 [子服务] [标识符] [数据]`，数据可含占位符 `{addr} {len} {crc}`。

## 方案文件
ECU 刷新方案为 JSON(格式 `myzcanpro-flash`),可自由命名扩展名,各 SID 参数均可编辑。

## 测试
`python tests/run_all.py`(GUI 测试使用桩 Qt,不依赖显示环境)。

## 报文监视 (Message monitor)
主界面「报文监视」: 实时查看总线上的收发报文，可与 UDS 诊断 / ECU 刷新 / 普通发送同时使用。
- 通道的接收线程每读到一帧，同时交给 UDS 队列和监视器（被动旁听，监视器自己不读设备，不会抢帧，也不改变诊断时序）；发送帧在发送时记录。
- **按ID覆盖显示**（默认）: 同一 ID（通道+方向+ID+帧格式）一行，新帧覆盖旧帧，并显示计数；取消勾选则按时间顺序滚动（最近 1000 帧）。
- **时间差**: 「与同ID上一帧」或「与上一帧(任意ID)」。接收帧使用设备时间戳（保留真实间隔），发送帧用主机时间。
- **实时保存**: 后台线程把每一帧追加写入 CSV（含时间、通道、ID、类型、方向、长度、数据）；「保存」导出当前显示。
- 可按通道 / ID / CAN类型 / 方向 / 数据筛选；「暂停」只冻结显示，计数与保存不受影响。
- **错误帧**: 总线错误帧显示为红色的「错误帧」行（每通道一行，内容显示为 xxx），计数即错误次数，「时间差」即错误帧出现的间隔（频率）；取消底部「显示错误帧」可隐藏；滚动模式下每个错误帧各占一行。能否收到错误帧取决于设备/驱动是否上报。

## 软件扫描 (多核板上各软件的信息/功能)
主界面「软件扫描」: 对板子上的各个软件（动力域控制器 7E2、驱动电机控制器 7E3、电驱充电模块 7E3、从驱动电机控制器 745，响应=物理+8，功能 7DF）读取 软件编码 / 软件版本 / 软件日期 / 故障码数量。
- **列表页**: 左侧勾选，底部「开始扫描 / 停止扫描」；未读取或读取失败显示 `-`；点软件名称改地址，点任一信息格子进入该项的「读取方式」编辑页；最右 `›` 进入该软件的功能页。
- **功能页**（上下级页面，不是弹窗，「‹ 上一级」返回）: 每个功能是一个按钮，点击即运行；「添加功能」进入编辑页（与 ECU刷新 的编辑器相同：编排 UDS 服务），「新建文件夹」建子菜单（点进去就像进文件夹）；「管理」模式下点按钮可编辑 / 重命名 / 删除。
- **执行器 = 一个 JSON 文件**（服务序列 + 结果显示：取哪一步的回复、跳过开头几个字节，当前只支持十六进制原文）。例如读 VIN：`10 03` + `22 F1 90`，回复 `62 F1 90 XX…XX` 显示为 `XX…XX`。
- **数据文件夹**（默认程序目录下 `scan_data`，可在界面里改）的层级就是界面层级: `<软件>/module.json`、`<软件>/信息/软件编码.json…`、`<软件>/功能/…`。首次运行自动生成上面 4 个软件和默认执行器（默认 DID: 软件编码 F188、版本 F189、日期 F199，故障码数量 `19 01 08`，请按你们的实际 DID 修改）。
- 扫描/运行时占用所选通道，期间 UDS诊断/ECU刷新 窗口不能同时使用该通道（结束后自动释放）。

## 主界面布局
菜单（设备管理 / UDS诊断 / ECU刷新 / 软件扫描 / 普通发送 / 报文监视 / 校验码计算工具）在界面上方，点击后在界面内新开一个标签页（标签栏在下方，再次点击只切换到已打开的标签）；「设备管理」标签固定不可关闭。标签页右下角「⇱ 浮动」或双击标签可把该页变成独立窗口（窗口里「⇲ 停靠回主窗口」放回标签栏）。关闭标签即关闭该工具；正在刷写时会拒绝关闭。

## CAN FD 说明
- ISO-TP 单帧：≤7 字节的请求按经典单帧格式（`03 22 F1 90 ...`，8 字节 FD 帧）发送；8~62 字节才用扩展单帧头（`00 LL ...`）。早期版本把短请求也写成 `00 03 22 F1 90`，不符合 ISO 15765-2，ECU 不会应答。
- 设置里「CAN FD 诊断帧使用 BRS」可关闭位速率切换；「ISO-TP FD 帧长度」设为 8 则在 FD 通道上改发经典 CAN 帧（ECU 只认经典帧时用）。

## 安全访问 (密钥 DLL 与 EcuSerialNum.txt)
计算密钥的 DLL（`ZLGKey`）每次调用都会读取**其工作目录**（默认 exe 同文件夹，可在 27 步骤里改「DLL 工作目录」）下的 `EcuSerialNum.txt`：
- **第 1 行** 序列号：本次运行里**第一次**安全访问前用 `22 <DID>` 读取（默认 `F1 8C`，设置 → 安全访问 可改 DID / 文件名 / 序列号格式 ASCII 或十六进制）并写入；之后的安全访问（含其他 ECU）不再读取，第 1 行保持不变。ECU 消极应答 → 第 1 行为空（视为已读取，不再重试）；读取超时无应答 → 第 1 行为空，但下次安全访问会再试一次。
- **第 2 / 3 行** 软件编号：按**被解锁 ECU 的物理地址**查「设置 → 安全访问 → 编号映射表」，种子 2 字节时 DLL 取第 2 行，16 字节时取第 3 行。默认 `7E2:[0,0]  7E3:[1,2]  785:[2,4]  645:[1,3]`，可增删行；**物理地址不在表里会直接报错**（不发送、不写文件，避免错误密钥消耗 ECU 尝试次数）。
- 读序列号发生在 `27` 的 seed/key 事务**之前**且不占用请求锁，所以会话保活（3E 80）不受影响；seed 与 key 仍在同一个锁内连续完成。
- 程序启动时和退出时都会删除该文件；是否删除不影响正确性（"是否已读取"是每次运行的内存状态，第一次安全访问一定会重写第 1 行）。
- 原先在安全访问步骤里的「通过 F1 8C 写入序列号」勾选项已取消，以此处为准。旧的配置文件如果保存了旧的映射关系，请在设置表里核对。
